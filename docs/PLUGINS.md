# DSH 与插件

主路径为 Chatagent → 本机桥接 → DSH 专用聊天会话。DSH 统一负责模型调用、工具注册与插件执行，Chatagent 负责消息和客户端交互。安装与接口说明见 [DSH-BRIDGE.md](DSH-BRIDGE.md)。

## 配置与权限

DSH 中安装的记忆等插件由使用者在 DSH 中配置。Chatagent 的聊天设置按插件来源分组显示可用工具、说明和开关；授权仅作用于对应聊天，新聊天不会默认获得全部工具。DSH 自身的内部工具不作为用户自制插件展示。

自制插件可提供独立配置页，例如课表更新、媒体活动和记事本。当前保留对显式提供的 WeChatAgent API v2 插件目录的适配；外部插件源码、私人配置和运行资料不随仓库分发。插件卡片提供配置入口，实际运行仍需要相应处理器和宿主服务。

## 记忆

长期记忆交给使用者安装的引擎。当前验证过鱼 1.5.0 的召回、remember 与原生条目迁移；其他版本和引擎需要自己的适配验证。鱼使用上游独立许可，代码没有合入 Chatagent。

近期上下文窗口和话题摘要属于 Chatagent 的会话管理。窗口外的原始聊天仍保存在消息档案中；缩小窗口不会删除历史。摘要或检索机制的存在不等于长期记忆质量的评测结论。

## 通知与扩展

DSH 插件可以依赖 `chatagentBridge` 服务，通过 `publish({sessionId,deliveryId,text,attachments?})` 投递消息。会话必须与对应桥接匹配，deliveryId 必须稳定唯一。保存与确认表示本机接收，不代表手机已读。

接入新插件时应说明所需服务、授权范围、资料目录、外部调用及备份方式。网页面板、定时任务、账号服务和文件访问能力都需要宿主支持，不能仅凭“兼容 DSH”就推定它在所有运行方式下可用。

## 兼容路径

`scripts/start-workspace.mjs` 和 `scripts/start-standby.mjs` 保留独立 SDK 宿主模式；只有明确配置的代码和资料目录会被读取。独立工作目录是资料隔离，不是操作系统沙箱。新部署优先使用本机 DSH 桥接方式。
