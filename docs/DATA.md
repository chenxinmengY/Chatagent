# 资料与迁移

电脑 dataRoot/chat/chat.sqlite 保存客户端消息、设置和导入档案；chat/attachments 保存附件对象及索引。主路径中 DSH 专用会话、插件记忆和桥接归档有各自的目录，见 [DSH-BRIDGE.md](DSH-BRIDGE.md)。多角色聊天分别绑定会话及权限，不能默认合并其他角色的资料。旧独立 SDK 模式另在 dataRoot/dsh 下保存原生日志和工作目录。

手机保存已同步消息、草稿、待发与附件缓存。设置中的存储清理仅删除已完成消息对应、可重下的缓存对象；草稿、待发和未知对象会保留。它不会删除电脑的消息或附件原件。外观是各设备自己的设置。

## 便携资料

电脑设置页可导出 `chatagent-portable-v1` JSON，包含当前聊天、已导入历史、鱼条目、人格和日记，以及来源身份和内容摘要。它不包含模型密钥、插件可执行代码或附件原文件。附件只有关联元数据，导入报告会将原件缺失列出。需要完整搬家应使用联合备份。

导入顺序为选择来源 → 预检数量、来源、重复、冲突、未知时间和缺失附件 → 导入档案。重复项不重复写入，同一来源身份内容变化会阻止本批次。旧聊天进入统一查询时间线，旧工具消息保留为上下文档案，不执行。未知时间明确显示时间不详。

- Chatagent 便携包：校验 `digest = SHA256(JSON.stringify(records))`，保留所有记录字段。
- WeChatAgent：已有捕获档案在当前空间中可直接查询。文件转换接受 `wechatagent-history-v1` 包装，sourceId、scope、messages 必填；messages 中保留 seq、at（秒）和 body（text、outgoing）。它不直接破解微信、QQ数据库。
- AstrBot：选择控制台会话导出的 JSONL，在界面中选一个会话；实例名称区分不同部署。保留 cid、user_id、原始 content 和会话元数据。上游未给逐消息时间时保留未知，不能拿会话更新时间冒充每条时间。多模态结构保留原件，不自动下载外部链接。
- 鱼记忆：导入档案后另行选择一个来源，预检并合并到当前鱼。只支持明确标记的 1.5.0 原生条目，保留删除及修订字段。同 ID 不同内容拒绝覆盖，不自动复活已删条目。其他引擎的资料保留为档案，不冒充已经启用的记忆。

人格、日记和其他记忆引擎条目作为档案保存，不会擅自替换当前人格或转换算法。当前不自动从旧聊天调用模型生成新记忆。便携内容可能本来就含聊天中的个人信息，请由资料所有者自行选择分享范围。

## 完整备份和恢复

聊天页「备份此空间」会等待当前轮次落盘，冻结新写入并保存相应范围。主桥接模式覆盖 Chatagent 消息、附件及配置，DSH 会话和插件记忆需另行备份；旧独立 SDK 模式可包含其独立 DSH 状态。备份清单列明覆盖范围、文件大小和摘要。备份不等同于公开源码包。

```powershell
node scripts/restore-runtime-backup.mjs C:\ChatagentData\backups\backup-id C:\ChatagentRestored
```

目标必须不存在。恢复会更换同步代号，保留数据来源标识，并将未结束工作转成待核对状态；不会自动执行旧任务。恢复后设备重新配对，原手机草稿和待发内容保留，由用户处理状态冲突。
